## 2. 四层导航（课程 = 项目）

```
课程（一堂课，名字就是课名）
├─ 备课对话 ×N      可以有好几段，聊崩了重开，旧的留着
├─ 课堂             挂在课程上，由某段备课对话「导入」而来
└─ 复盘对话 ×N
```

- 对话是**过程**，可以多段；课堂和复盘是**这堂课的档案**，各一份。
- 「导入到课堂」是**单向**的：对话 → 课堂。重新导入覆盖课次卡，对话原文永不改。
- 课堂视图里**没有对话输入框**——不是禁用，是这个视图里不存在会话对象。

### 2.1 挂靠是硬门槛

未挂靠的对话（`courseId: null`）在「待整理」里。点「整理并挂靠」→ 服务端按词重合度给出候选课程与依据 → 人确认 → 才允许导入课堂。服务端对未挂靠的导入请求直接返回 **409**。

挂靠不是搬文件，是给 `courseId` 赋值，所以对话不会因移动丢失，也不会出现两个副本。

## 4. 旁听者（watcher）

**它不是对话。** 老师一直在说，它一直在听，绝大多数时候什么都不输出。

```
每 2 秒醒一次
  ├─ 从桥里收新事件（顺带入课）
  ├─ 有新 utterance 吗？没有 → 睡（不花一分钱）
  ├─ 距上次判断不足 12 秒？ → 攒着
  └─ 够了 → 调一次模型，只问两件事：
       note：这段有没有值得记下的事实？
       speak：此刻开口能不能让老师立刻做对一件事？
```

### 4.1 时机由规则定，措辞由模型定

```
规则先认：同一问题第 3 遍 / 时长被改成 ≥20 分钟 / 候答超时
   └─→ 硬触发，模型这次必须给一句（不许返回 null）
规则没认出来
   └─→ 模型自由裁量，可以一句话都不说
```

**为什么**：第一版全交给模型判断，结果它一句都不敢说。时机是能被物理量判定的，措辞才需要理解力。

### 4.2 三道闸

| 闸 | 值 | 防什么 |
|---|---|---|
| 无新输入不调模型 | — | 白花钱 |
| 判断间隔 | 12 秒 | 每句话都想一遍 |
| 每课推送上限 | 8 句 | 变话痨 |

## 5. 眼镜桥（文件版）

```
agent/bridge/
├─ lesson-card.json   电脑 → 眼镜   这节课怎么上（含 startWhen、waitSeconds）
├─ events.jsonl       眼镜 → 电脑   老师原话 + 课堂事件，只追加
├─ status.json        眼镜 → 电脑   心跳，3 秒一次
└─ outbox.jsonl       电脑 → 眼镜   旁听者决定要说的那句话
```

**为什么不用 HTTP**：眼镜在 WSL2（NAT），电脑端绑 `127.0.0.1`，回连要过防火墙。`/mnt/c` 零配置、不怕墙、断了只是慢一点。代价是 1–2 秒轮询延迟。

**记账方式**：`_sync.json` 存已收的行号；重新下发本课卡会重置起点并清空 outbox，不会把上节课的话带进新课堂。

眼镜侧对应的路径是 `/mnt/c/Users/YanHang/Desktop/黑客松/agent/bridge/`。

## 7. 模型接入

- 一律走 OpenAI 兼容 `/chat/completions`。地址自适应：填域名、填到 `/v1`、填全路径都认；`?GroupId=xxx` 这类附加参数单独一栏。
- `reasoning_effort` 可配。当前 `low`——首字从 4.6 秒压到 1.7–2.4 秒。
- 流式剥掉 `<think>…</think>`，`reasoning_content` 一律忽略（有的推理模型会把思考写进正文）。
- 服务商不认 `reasoning_effort` 时，400 后自动去掉该参数重试一次。

## 9. 明确不做

- 学情诊断、情绪判断（没有信号）
- 多教师云端同步（本地优先）
- 自动环节规划（必须老师确认）
- 把知识库做成 RAG 大工程（关键词够用，且可解释）
